End-to-end POCDecentralized identityPersonal build · 2025–now

IDTrust: decentralized identity wallet

I designed and built an end-to-end identity wallet as a proof of concept: backend, frontend, data, QR verification and deployment.

  • Identity for humans, machines and AI agents needs a wallet that holds credentials the holder controls and that a verifier can check quickly.
  • I wanted to prove the whole path works in one system, not hand a spec to someone else to build.
  • A Java 21 and Spring Boot backend exposes JSON APIs through Jackson. PostgreSQL stores identities and credentials.
  • A React and TypeScript frontend handles the wallet. QR-based verification uses ZXing.
  • The app is containerized and deployed on Kubernetes.
  • A GitHub Actions pipeline builds, tests and deploys on every change, so the POC runs the same way every time.

GenAI · AgenticThe Hashgraph Group2025–now

Flowgenix-AI

A multi-agent GenAI system that turns dense carbon-credit methodology documents into executable workflows.

  • Before a carbon methodology could go live on a registry, subject-matter experts translated a long methodology PDF into workflows, forms, eligibility rules and formulas by hand.
  • It took 4–5 months per methodology, the bottleneck for carbon-market onboarding.
  • Split the job across specialist agents instead of one general prompt: a parser builds a structured model, then generators produce BPMN, forms, validation rules, DMN and calculation logic.
  • Added human-in-the-loop checkpoints so experts review the output instead of writing it.
  • Processing dropped from 4–5 months to 1–2 days, about 98% faster.
  • The expert's role moved from writing every artifact to reviewing what the agents produce.

Approach

Understand the demand. Build the high-value solution.

I'm a Certified Scrum Product Owner, and I use frameworks as tools. These principles guide how I deploy.

AI makes building smoother, so the scarce skill is knowing what is worth building. I start with the people who feel the pain, confirm the demand, and prioritize the solution with the highest value. Then I show it as a working demo, not a deck.

A RAG answer that looks good is not evidence. I compare parsing, chunking and retrieval choices on the same documents and keep the one that measures best.

AI does the heavy lifting, and experts own the judgment calls. Flowgenix-AI is built around that split, because it is what makes the output trustworthy enough to use.

Containers, CI/CD and a clear runbook come with the build. If the client team can't operate it without me, the deployment isn't finished.
